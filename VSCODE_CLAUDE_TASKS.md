## Context

- **Generator:** Zensical 0.0.69 (pinned in `requirements.txt`). Preview with `zensical serve`, build with `zensical build --clean`.
- **Hosting:** GitHub Pages at <https://damom73.github.io/griffins-knowledge-repository/>, deployed by `.github/workflows/docs.yml` (created in task 5) on every push to `main`.
- **Audience:** Years 7–10, written at a Year 7/8 level. Australian English.
- **Sections:** OnStage, Rescue Line, Rescue Maze, Soccer and Tips are stubs for now. Other Robots holds the Using MakeCode guide and sequential lessons for the PU Robot (16), XGO Robot Dog (13) and WuKong Manipulator (11). PU Lessons 2, 9, 10, 12, 13, 15 and 16 are based on ELECFREAKS PU wiki cases (with hand-wave or clap triggers instead of button A, which can't be reached inside the head). PU Lessons 1 and 2 use three ELECFREAKS diagrams in `docs/assets/pu-robot/` (the robot's parts in Lesson 1, the remote controller in Lesson 2), credited in their captions. Lesson 2 (Remote Control Show) has no code. XGO Lessons 8, 9, 10 and 13 are based on the original XGO kit's wiki cases, updated for the V2 dog. The site plan is the `site-plan.md` doc in the user's "RobocupJr Website" Claude project.
- **Colour scheme** (from the Griffins logo, in `docs/stylesheets/extra.css`):
    - slate `#545F65`: banner (header and tabs) in both modes, with white text (6.6:1) and a white griffin logo
    - pale cyan `#B3E9FC`: text of the active or hovered tab (only the text colour changes, like the other tutorial sites)
    - magenta `#BA004C`: light-mode page titles (h1) and links
    - deep cyan `#0077A8`: light-mode section headings (h2–h4)
    - cyan `#00ADEF`: dark-mode page titles
    - pink `#FF4D94`: dark-mode section headings
    - sky `#7FD6F7`: dark-mode links
- **Callouts and code blocks:** the standard style shared by all the user's tutorial sites (six callout types: learn, terms, primm, note for Code explanation only, tip, warning).
- **Lesson template:** `learn` callout, `terms` callout (if new terms), short intro, then concept sections. Each example has `=== "Blocks"` and `=== "Python"` content tabs, then a PRIMM callout, then a collapsed `??? note "Code explanation"` that explains every Python line. Lessons end with `## Exercises`: a PRIMM modify callout, then question-style exercises, each with `Starter code:` and a snippet.
- **Blocks tab:** a screenshot at `docs/assets/blocks/<kit>/lesson_NN_<example>.png` with the class `{ .blocks }`, plus a "Blocks used:" line naming each block and its category. All screenshots are currently placeholders made by `scripts/make_blocks_placeholders.py`.
- **Python:** MakeCode Python, not MicroPython. Examples are in `docs/examples/other/<kit>/lesson_NN/<example>/main.py`. No structural comments (MakeCode turns comments into block comments). Event handlers come first and **on start** code last, the way MakeCode lays it out.
- **Exercise starters:** `docs/examples/.../exN_name/main.py`. `scripts/make_starter_comments.py` copies each exercise's wording into a comment block at the top of its starter. Run it after changing any exercise text. There's no student zip and no solutions page (the user chose starter code on the page only).
- **Checks:** `python scripts/check_explanations.py` (expect `0 issue(s) found`) and `zensical build --clean` (expect `No issues found`).
- **Glossary:** `docs/reference/glossary.md` is generated by `python scripts/build_glossary.py` from the Terminology callouts. Never edit it by hand.
- **Voice:** always "we" (the reader and writer learning together). "You" only in PRIMM steps, exercise questions and "your" in exercises.

## Tasks

### 1. Check the Python names in MakeCode

The Python in the examples was written from each extension's TypeScript source, using MakeCode's usual name conversion (camelCase to snake_case, enum members to CAPITALS). None of it has been pasted into MakeCode yet. For each kit, create a MakeCode project with the extension, paste each example into the Python view, switch to Blocks and back, and fix any name MakeCode changes. Report every change.

Names most likely to differ:

- XGO: `xgo.manipulator_clamp_x`, `xgo.manipulator_clamp_z`, `xgo.manipulator_clamp`, `xgo.servo_setting_robot_arm`, `xgo.get_posestate`, `xgo.set_posestate` (TypeScript: `Manipulator_clampX`, `Manipulator_clampZ`, `Manipulator_clamp`, `servo_setting_robotArm`, `GetPosestate`, `SetPosestate`), and the enum members `xgo.action_enum.SIT_DOWN`, `STRETCH_ONESELF`, `xgo.body_parts_enum.LEFT_FRONT`, `xgo.pose_enum.POSE1`.
- PU Robot: `robotPu.MoveDirection.RIGHT_TURN`, `robotPu.LightSelection.LIGHT1`, `robotPu.smooth_set_servo_angle`, `robotPu.enable_remote_control_with_group`, `robotPu.on_control_value_received`.
- WuKong: `wuKong.ServoTypeList._180`.
- Music (PU Lesson 12): `music.built_in_playable_melody(Melodies.ENTERTAINER)`, `music.PlaybackMode.IN_BACKGROUND`, `music.beat(BeatFraction.HALF)`, `music.set_tempo(120)`.
- Sensors and radio (XGO Lessons 9 and 13): `input.magnetic_force(Dimension.STRENGTH)`, `radio.send_value`, `radio.on_received_value`, `serial.write_value`.
- Local variables: some examples assign a variable inside a function without `global` (`angle` in WuKong Lessons 8 and 9, `choice` in WuKong Lesson 7). Blocks variables are always global, so check that these convert to Blocks. If not, add `global` and a starting value at the bottom of the program, the way PU Lesson 10 does with `distance`.

If a name changes, update the example, then search the pages for the old name (the XGO Lesson 6 and Lesson 8 warnings mention some by name). Re-run both checks.

### 5. Create the deploy workflow

The cloud session couldn't write inside `.github/`, so create `.github/workflows/docs.yml` with this content. Before committing, confirm that each action version exists (they're the versions `zensical new` generated):

```yaml
name: Deploy site
on:
  push:
    branches: [ main ]
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/configure-pages@v6
      - uses: actions/checkout@v7
      - uses: actions/setup-python@v6
        with:
          python-version: 3.x
      - run: pip install -r requirements.txt
      - run: zensical build --clean
      - uses: actions/upload-pages-artifact@v5
        with:
          path: site
      - uses: actions/deploy-pages@v5
        id: deployment
```
